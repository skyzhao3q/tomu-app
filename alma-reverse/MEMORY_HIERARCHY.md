# Alma (Protan) Memory Hierarchy: 短期メモリと長期メモリの使い分け

Alma（Protan）は、自律的に思考し過去の記憶を保持するため、複数の異なる階層のメモリ（記憶領域）を使い分けています。

## 1. 記憶の階層と保存形式

### ① `SOUL.md` (不変のアイデンティティ)
- **保存場所**: `~/.config/alma/SOUL.md`
- **保存形式**: Markdown
- **用途**: 私（エージェント）自身の根源的な性格、言葉遣い、外見、絶対に破ってはいけないルール。
- **読み込み**: アプリ起動時および毎回のチャット生成時に、システムプロンプトの**最上部**に静的に結合（Inject）されます。この記憶は最優先事項として処理されます。

### ② `USER.md` (ユーザープロファイル)
- **保存場所**: `~/.config/alma/USER.md`
- **保存形式**: Markdown (YAML Frontmatter 付き)
- **用途**: ユーザー（あなた）に関する確実な情報（名前、プラットフォームID、プログラミング言語の好みなど）。
- **読み込み**: 毎回のプロンプト合成時に `SOUL.md` と並んで**必ず**コンテキストに挿入されます。これにより、毎回「私の名前は？」と聞かれても即答できます。

### ③ `MEMORY.md` と `memory/YYYY-MM-DD.md` (長期ファイルメモリ)
- **保存場所**: `~/.config/alma/MEMORY.md` および `~/.config/alma/memory/` 配下のファイル
- **保存形式**: Markdown
- **用途**: 日々の出来事や長期的に覚えておきたい重要な文脈を、人間が読める形式で保存します。
- **読み込み**: コード解析の結果、メインプロセスはチャットプロンプト生成時に**自動的に**「今日」と「昨日」の `memory/YYYY-MM-DD.md` ファイル、および `MEMORY.md` (サイズが4バイト以上の場合) を読み込み、`## Long-term Memory` としてプロンプトに注入していることが判明しました。

### ④ Vector Memory (セマンティック RAG メモリ)
- **保存場所**: `sqlite-vec` によるローカルDB (`memories` テーブル)
- **用途**: ファイルベースの記憶に収まらない過去のすべての雑談や細かいコンテキストを「意味」で検索するための大規模記憶層。
- **読み込み**: ユーザーの質問に対して自動的に類似度検索が行われ、関連性の高い過去の会話スニペットだけが動的に抽出されてプロンプトに挿入されます。

### ⑤ Threads (短期メモリ・会話履歴)
- **保存場所**: `~/.config/alma/threads/` および Workspaceの `.alma-snapshots/history.json`
- **保存形式**: Markdown および JSON
- **用途**: 現在進行形の「今の会話」の履歴。
- **読み込み**: API (`GET /api/threads/:id`) を通じてUIに表示されるほか、AIモデルに送信する「メッセージ履歴（`messages` 配列）」としてそのまま直近数十ターン分が渡されます。

---

## 2. 記憶の使い分け（実装設計のキモ）

プロタンを設計する上で、なぜこれほど多くの記憶層が分かれているのでしょうか？

1. **幻覚（ハルシネーション）の防止**:
   「自分の性格」や「ユーザーの名前」など、**絶対に間違えてはいけない情報**は、RAG（ベクトル検索）に任せず、物理ファイル (`SOUL.md`, `USER.md`) として毎回のプロンプトに必ず含めます。
2. **トークン節約 (Context Window の最適化)**:
   昨日起きたことや重要な記憶 (`MEMORY.md`, `YYYY-MM-DD.md`) は直接テキストとして読み込みますが、それ以前の膨大な会話は必要な時だけ `sqlite-vec` で検索して挿入（RAG）します。これにより、AIが「パンク」するのを防ぎます。
3. **短期記憶の確実性**:
   直近の会話（Threads）はそのまま API に渡すことで、「さっき言ったじゃん」という短期的な文脈を完璧に維持します。

**【結論】**
Almaは、**Static Files (SOUL/USER) + Dynamic Text (MEMORY/Daily) + Vector DB (sqlite-vec) + Current Thread (JSON)** という4層のメモリをプロンプト合成時に統合することで、「人間らしい記憶と連続性」を実現しています。
